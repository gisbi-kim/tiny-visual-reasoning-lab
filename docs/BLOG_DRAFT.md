# 사진 여섯 장과 자연어 조건으로 decision model 학습하기

> 작성 중인 원고이다. v2의 최종 평가가 끝나면 결과 표와 학습 기록을 채워 `BLOG.md`로 완성한다. 아래에 없는 최종 수치를 추정하여 넣지 않는다.

## 1. 풀고 싶은 문제

사진을 분류하는 모델은 보통 한 장의 사진을 입력받아 고양이, 바나나 등의 이름을 출력한다. 이번에는 사진을 여섯 장 놓고, 자연어로 주어진 조건에 맞는 위치를 고르게 하였다. 예를 들어 다음과 같은 사진판을 생각해 보자.

| | 왼쪽 | 가운데 | 오른쪽 |
|---|---|---|---|
| 윗줄 | A: 개 | B: 바나나 | C: 고양이 |
| 아랫줄 | D: 구명보트 | E: 금붕어 | F: 배낭 |

“고양이 사진을 골라”의 답은 C이다. “고양이에서 왼쪽으로 한 칸, 그다음 아래로 한 칸 이동해”라고 하면 C → B → E 순서로 따라가야 한다. “동물 사진이 세 장 이상이면 바나나를, 아니면 배낭을 골라”의 답은 B이다. 개, 고양이, 금붕어가 동물에 해당하기 때문이다.

이때 세는 것은 **동물이 나온 사진의 수**이다. 한 사진에 여러 동물이 있더라도 중심 대상 하나로 표현한다. 격자 밖으로 이동하거나 조건에 맞는 사진이 없으면 NONE을 선택한다. 출력 공간은 A, B, C, D, E, F, NONE의 일곱 가지이다.

## 2. 기본 모델과 우리가 학습하는 부분

기반 모델은 Qwen3.5-4B이다. 이 모델은 이미지와 텍스트를 함께 처리할 수 있다. 여기에 LoRA와 Clef 방식의 선택용 head를 붙였다. 입력 사진과 자연어 지시에서 표현을 계산한 뒤, 선택용 head가 각 선택지의 점수를 내는 구조이다.

여기서 Clef는 head의 구조와 입력 형식을 뜻한다. Cloudflare가 배포한 완성형 Clef 모델의 가중치를 가져온 실험은 아니다. v1은 Qwen의 사전학습 가중치에 새 LoRA와 head를 붙여 학습했고, v2는 그 학습 결과를 이어받았다. [실제 모델 생성 코드](../train.py)와 [배포 추론 코드](../engine.py)를 공개한다.

Head는 단순한 7출력 선형층보다 복잡하다. 입력 hidden size는 2,560, head 내부 폭은 512이고, routing 2층·decoder 4층·attention head 8개·feed-forward 폭 2,048을 사용한다. 입력 sequence의 hidden states와 질문·선택지 span을 이용해 선택지별 점수를 만든다. 선택지 span은 입력의 token 위치이며 정답 위치를 의미하지 않는다. [Head 참조 구현](../clef_reference.py)에서 구체적인 연산을 확인할 수 있다.

```text
2×3 사진 격자 + 자연어 지시 + 선택지 정의
                 ↓
       Qwen3.5-4B + 학습한 LoRA
                 ↓
          학습한 Clef head
                 ↓
         A B C D E F NONE 점수
```

앱에서 Qwen이 자유로운 설명문을 생성하는 것은 아니다. 또한 정답을 만드는 규칙 프로그램을 앱에 넣어 대신 계산하게 하지 않았다. 규칙 프로그램은 학습 데이터의 정답을 만들고 검사하는 데 사용한다. 실제 예측 경로에는 사진과 사용자가 입력한 문장만 들어간다.

학습은 정답 선택지를 알려 주는 지도학습이다. 일곱 점수에 softmax를 적용한 확률을 p라고 하면, 정답 a*에 대한 loss는 −log p(a*)이다. 틀린 선택에 높은 확률을 줄수록 손실이 커지고, 그 gradient로 LoRA와 head를 갱신한다. 사람이 작성한 단계별 사고 과정을 생성하도록 학습한 것은 아니다.

LoRA는 사전학습 가중치 W를 고정한 상태에서 작은 행렬 A, B를 학습하여 W + (alpha/r)BA 형태로 가중치의 변화를 표현한다. 이번에는 rank와 alpha를 모두16으로 두었다. LoRA 32,464,896개와 선택용 head 32,046,596개를 학습하여 합계64,511,492개가 학습 대상이다. 기본 모델·LoRA·head를 포함한 논리 파라미터4,603,777,028개 중 약1.40%에 해당한다.

4bit 양자화는 저장과 연산에 필요한 메모리를 줄이는 방법이다. 4bit로 저장했다고 파라미터의 개수 자체가 줄어드는 것은 아니므로, 학습 비율의 분모는 압축된 텐서의 저장 원소 수와 구분하였다.

## 3. 사진보다 먼저 정해야 하는 의미

원본은 Tiny ImageNet이다. 200개 클래스 중 작은 사진에서도 대상이 비교적 분명한40개 클래스를 사용하였다. 원본 bounding box로 중심 대상을 잘라 비율을 유지한 채 격자에 배치하고, 너무 작은 대상과 RGB가 완전히 같은 중복 사진을 제외하였다. 원본 해상도는64×64이므로 확대하더라도 실제 세부 정보가 새로 생기는 것은 아니다.

사진마다 어떤 범주에 속하는지 명시적인 표를 만들었다. 예를 들어 금붕어는 물고기이면서 동물이다. 곰 인형은 동물 사진으로 세지 않는다. 이 정의가 불명확하면 “동물이 몇 장인가”라는 문장에 대해 정답부터 일관되지 않게 된다.

클래스 표본과 문장 틀은 코딩 에이전트가 검토하였다. 모든 사진을 사람이 독립적으로 검수한 데이터는 아니다. 가려진 물체나 배경에 있는 다른 물체 때문에 실제 이미지의 의미가 모호할 수 있다는 한계는 남는다.

## 4. 자연어와 정답을 함께 만드는 방법

먼저 문장과 독립적인 의미 프로그램을 만든다. 예를 들어 앞의 C → B → E 문제는 다음과 같이 쓸 수 있다.

```json
{"family":"chain","anchor":"cat","direction":"left","second_direction":"down"}
```

사진판의 대상 목록에 이 프로그램을 실행하여 정답을 구하고, 같은 프로그램을 여러 문장으로 표현한다. 문장을 만드는 함수에는 정답을 전달하지 않는다. 방향이나 대상을 바꿨을 때 정답이 달라지는 문제 쌍도 함께 만든다. 같은 사진판이라도 지시를 제대로 읽어야 답할 수 있도록 하기 위해서이다.

v2에서는12개 조건 유형에 대해 한국어·영어 각각6개의 문장 틀을 사용한다. 총144개의 틀에 대상 이름, 범주, 요청 표현을 조합한다. “3장/세 장”, “3/three”, “왼쪽/좌측”과 같은 표기도 섞었다. 이 수치는 세상의 모든 자연어 표현을 다루었다는 뜻은 아니다. 범위를 정하고 그 범위 안의 표현을 고르게 공급한 합성 데이터이다.

원본 사진12,830장으로 격자4,825장을 만들고, 여기에 지시와 정답을 붙여37,632개의 학습 예제를 만들었다. 서로 다른 문장은36,328개이다. 한 격자에 여러 지시를 붙이므로 원본 사진 수, 격자 수, 학습 예제 수는 서로 다르다.

## 5. v1에서 v2로 바꾼 이유

v1에서는 일부 문장 틀과 두 조건 조합을 학습에서 제외하였다. 가령 “고양이 왼쪽 사진”을 학습한 뒤 “고를 사진 오른쪽에 고양이가 있어야 한다”는 표현도 이해하는지 확인하려는 목적이었다. 같은 행에서 범주를 찾은 다음 한 칸 이동하는 조건도 별도로 보류하였다.

두 버전의 데이터 크기도 함께 보자. v2는 단순히 같은 예제를 한 번 더 반복한 실행이 아니라, 사용할 표현과 조건의 범위를 넓혀 새로 구성한 데이터로 이어서 학습한 실행이다.

| 학습 데이터 | v1 | v2 |
|---|---:|---:|
| 원본 사진 | 12,023장 | 12,830장 |
| 2×3 사진판 | 4,024개 | 4,825개 |
| 지시·정답 예제 | 31,360개 | 37,632개 |
| 서로 다른 문장 | 29,350개 | 36,328개 |

사진 수는 각 버전 안의 고유 개수이다. 같은 학습 사진 풀을 사용하므로 두 열을 더해 전체 고유 사진 수로 삼으면 안 된다. [v1 집계](data-summary.json), [v2 집계](v2-data-summary.json)에 세부 구성을 남겼다.

이 설계는 배운 내용을 새로운 표현과 조합에 적용하는 능력을 조사할 때 유용하다. 반면 사용자가 실제로 입력할 것으로 예상하는 표현까지 제외할 필요는 없다. v2에서는 지원할12개 조건과144개 표현을 모두 학습하는 방향으로 바꾸었다.

여기서 표현의 분할과 사진의 분할을 구분해야 한다. 표현을 모두 학습시키더라도 평가 사진까지 학습에 넣을 이유는 없다. 원본 사진 ID와 전체 RGB hash를 기준으로 학습·검증·보정·평가를 분리하였다. v1 평가 사진은 v2 학습에 들어가지 않는다.

## 6. 한 에폭의 의미와 실제 학습

이번 v2는 사전학습 모델에서 곧바로 시작한 첫 학습이 아니다. v1에서 검증으로 선택한 step2400의 LoRA와 head에서 이어서 학습한다. 계획한 추가 학습량은37,632예제, batch8, 4,704step으로1epoch이다.

한 epoch는 각 예제를 한 번씩 사용하는 단위이다. 같은 원리를 한 번만 본다는 뜻은 아니다. 조건 유형 하나당3,136개 예제가 있으며, 서로 다른 사진과 표현에서 같은 원리를 반복하게 된다. 가중치도 한 epoch 안에서4,704번 업데이트한다.

기반 VLM은 이미 이미지·언어에 관한 큰 규모의 학습을 거친 상태이다. 예전 ImageNet 분류 사전학습이 주로 시각 특징을 전달했다면, VLM은 이미지와 언어의 대응 및 지시 처리 능력도 가져온다. 적은 추가 학습으로 이 작업에 적응할 수 있는 이유로 생각할 수 있다. 다만 이번 실험은 그 기여를 분리해 측정한 실험이 아니며, 파인튜닝 전 순수 Qwen 대조군을 실행하지 않았다. LoRA 역시 적은 epoch로 충분하다는 보증이 아니라 파라미터 효율적인 적응 방법이다.

실제 장비는 Windows의 RTX4070TiSUPER16GB 한 장, Ryzen79800X3D, RAM64GB이다. NF4 4bit로 기본 모델을 읽고 BF16으로 계산한다. LoRA 학습률은1e-4, head 학습률은5e-5이며 cosine schedule을 사용한다.

최종 글에는 실제 run 시간, 완료step, 선택step, 최대 할당/예약 메모리를 JSON 기록에서 넣는다. 전체 run이 끝났더라도 검증 점수가 가장 좋았던 중간 체크포인트를 배포할 수 있다. 그 경우 선택 이후 업데이트는 배포 모델에 포함되지 않으므로, 전체 학습 시간과 배포 모델이 실제로 본 예제 수를 구분해 적는다.

## 7. 무엇이 얼마나 좋아졌는가

사용자가 궁금했던 비교는 기존의 세 평가 문제를 그대로 다시 풀렸을 때의 변화이다. 사진·문장·정답이 동일한1,120개씩을 사용한다.

| 기존 평가 구분 | v1 | v2 최종 | 변화 |
|---|---:|---:|---:|
| 새 사진 + 같은 뜻을 바꿔 쓴 표현 |79.29%|평가 후 입력|평가 후 입력|
| 새 사진 + 새로운 조건 조합 |67.77%|평가 후 입력|평가 후 입력|
| 새 사진 + 바꿔 쓴 표현과 새로운 조건 조합 |54.82%|평가 후 입력|평가 후 입력|

v2에서는 위 표현과 조합을 학습했다. 따라서 v2의 점수는 해당 유형을 학습한 효과를 보여 준다. 여전히 보지 못한 표현이나 작업 조합에 대한 일반화 점수라고 부르면 안 된다. 사진은 새 사진으로 유지된다.

별도로 모든 유형을 균형 있게 포함한v2_test2,016문제에도 v1과v2를 실행한다. 이 표와 위 표는 서로 다른 문제 집합이므로 한쪽의 v1 점수와 다른 쪽의 v2 점수를 빼서 개선 폭을 계산하지 않는다.

중간에는 고정 표본56개씩을 CPU로 평가한다. 표본 점수는 방향을 살펴보는 자료이며 전체1,120개의 결과를 대신하지 않는다. 중간 결과를 보고 학습 설정이나 체크포인트 선택 기준을 바꾸지 않는다. 최종 비교는 저장한 가중치를 별도 프로세스에서 다시 읽어 양쪽 모두 같은 CUDA 배포 코드로 수행한다.

## 8. 전체 정확도만으로 알 수 없는 것

대상 찾기, 두 단계 이동, 개수 분기, 범주별 개수 비교는 서로 다른 어려움이 있다. 최종 글에서는 조건 유형·언어·정답 선택지별 결과를 함께 살펴보고, 실제로 틀린 지시와 예측을 기록한다. 실패 사례는 결과 파일의 순서에서 처음 나오는 사례를 사용하여 보기 좋은 예제만 고르지 않는다.

선택 확률은 별도의1,008개 보정 데이터로 temperature를 조정한다. 양의 scalar로 점수를 나누므로 가장 큰 점수의 위치는 바뀌지 않는다. 즉 이 보정은 top-1정확도를 직접 올리는 방법이 아니라 확신의 정도를 조정하는 절차이다.

모델이 내부적으로 어떤 계산 경로를 사용했는지는 선택 정확도만으로 증명되지 않는다. 사진과 지시의 의미를 얼마나 일반적으로 조합하는지도 작성한 문제 범위 밖에서 별도 확인해야 한다. 근접 중복이나 기반 모델의 ImageNet 사전학습 노출 여부까지 완전히 배제한 실험은 아니다.

## 9. v1과 v2에서 얻은 교훈

이번 실험의 관심사는 높은 정확도 하나를 얻는 데 그치지 않는다. 이미 시각과 언어를 학습한 VLM을 사용하면, 원하는 판단 작업의 예제를 잘 구성하여 비교적 짧은 추가 학습으로 행동을 조정할 수 있는지 살펴보았다.

v1은 일부 표현과 조건 조합을 보류해 두었다. 이 경우 새 표현79.29%, 새 조건 조합67.77%, 둘을 함께 바꾼 경우54.82%였으며, 지원하려는 입력 중 어떤 부분에 학습 경험이 부족한지 확인할 수 있었다. v2에서는 같은4B 기반 구조와 기존 LoRA/head를 유지하면서 해당 표현과 조합을 학습 데이터에 포함하였다. 한정된 작업에서 부족했던 학습 경험을 구체적인 예제로 보완한 셈이다.

1,600step 중간 모델의 고정56문제씩에서는 v1 대비 새 표현76.79%→96.43%, 새 조합69.64%→98.21%, 표현·조합58.93%→98.21%로 개선되었다. 이 결과는 작은 표본이고v2는CPU,v1은저장된CUDA예측이므로 잠정적인 관찰이다. 최종 원고에서는 같은1,120문제 전체의 최종GPU비교를 주된 근거로 놓고, 이 중간표본은 개선과정을 보여주는 보조자료로 남긴다.

여기서 실용적인 장점은 이미 학습된 시각·언어 표현을 활용하여, 작업에 맞는 입력과 정답의 대응을 추가로 가르칠 수 있다는 점이다. v2의 실제 추가 시간과 데이터양, 개선폭을 함께 제시해야 이 장점이 어느 정도인지 판단할 수 있다. 데이터는 정답이 일관되고, 실제 사용할 표현·조건을 포함하며, 다양한 사진에서도 같은 규칙이 유지되도록 구성해야 한다. 이번에 방향·임계값·대상을 바꾼 대조쌍과 한·영 표현의 균형을 둔 이유도 여기에 있다.

해석의 범위도 정해 둘 필요가 있다. v2는 v1에서 보류했던 문제 유형을 실제로 학습했으므로, 개선을 새로운 모든 조합을 추론하는 능력의 향상이라고 말할 수는 없다. 또 이번 v2는 v1의 학습 결과를 이어받았으며, 전혀 파인튜닝하지 않은Qwen과의 직접 비교는 수행하지 않았다. 따라서 이 실험은 **기존 VLM 기반 decision model에서 부족한 표현·조건을 데이터로 보완했을 때 나타난 적응 효과**를 보여 주는 사례로 해석한다.

두 번째 중간 검사에서는 검증으로 선택된 2,000 step 가중치로 같은 표본을 풀렸다. 새 표현은 98.21%, 새 조합은 98.21%, 표현·조합은 94.64%였다. 1,600 step 결과와 비교하면 새 표현은 한 문제 더 맞혔고, 표현·조합은 두 문제 덜 맞혔다. v1보다 개선된 상태라도 모든 항목이 학습량에 따라 단조롭게 좋아지는 것은 아니다. 작은 표본의 변동과 조건별 차이를 확인하고, 최종 전체 평가를 따로 두어야 하는 이유이다.

## 10. 가중치의 출처와 다시 실행하기

기본 Qwen 모델은 Hugging Face의 고정revision에서 받는다. 우리가 학습한 LoRA와 Clef head, processor, 보정값은 이 프로젝트의 GitHub Release에서 받는다. 원본 Tiny ImageNet 사진은 Stanford에서 별도로 내려받는다. GitHub의 작은 코드 저장소를 clone했다고 기본 모델 전체가 함께 내려온 것은 아니다.

첫 실행 후 빨라지는 것은 저장된 기본 모델과 학습 가중치를 다시 사용하기 때문이다. 실행할 때마다 학습을 다시 하는 구조가 아니다. 최종 글에는 각 파일의 다운로드 크기, hash와 설치 명령을 실제 배포 manifest에 맞춰 넣는다.

CPU/MPS 경로는 float32 모델을 사용하므로 기본 모델 자체만 약18.3GB가 필요하다. 실제 Mac에서 동작과 속도를 검증하지 못했으며,16GB Mac에 충분히 들어간다고 보장하지 않는다.

## 11. 코드와 기록을 남기는 기준

코드뿐 아니라 데이터 집계, 학습 설정, 기록된loss와 검증 추이, calibration, 최종 예측, 실패 사례, 환경과 다운로드 검증을 함께 남긴다. 학습 중 모든 microbatch의 입력과 예측을 저장한 것은 아니므로 기록되지 않은 과거 예측을 사후 생성하여 로그처럼 제공하지 않는다.

본문은 이해를 위한 설명이고, 수치의 근거는 기계 판독 가능한JSON과 로그이다. README에서 블로그와 상세 자료로 바로 이동할 수 있도록 연결한다. 다른 사람이 같은 모델을 내려받고, 같은 평가를 실행하고, 주장과 실제 기록을 대조할 수 있는 수준을 목표로 한다.
