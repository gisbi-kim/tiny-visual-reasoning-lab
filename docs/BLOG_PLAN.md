# Tiny Visual Reasoning Lab 글과 실험 기록

사용자 요청(2026-11-03): 학습 완료 후 블로그 글을 쓰고, 통계·학습 과정·로그를 GitHub와 README에서 찾아볼 수 있도록 정리한다. 문체는 친절하고 차근차근 설명하는 공학 글로 한다. 과장된 성능 홍보나 문답식 문장 대신 정의, 작은 예제, 설계 이유, 구현, 실측, 한계를 순서대로 연결한다.

이전 사례는 [MNIST decision model 튜토리얼](https://gisbi-kim.github.io/jev-mnist-tutorial/)이다. 원본 프로젝트의 `docs/tutorial-plan.md`와 문서 구성을 확인했다. 기존 MNIST 저장소와 개인 홈페이지 본문을 수정하지 않고, 이번 프로젝트에 독립적인 글과 공개 자료를 둔다.

## 최종 산출물

- `docs/BLOG.md`: 최종 실측을 반영한 한국어 기술 글. 아래 초안을 사람이 읽을 수 있는 본문으로 완성한다.
- `site/index.html`: 같은 글을 읽기 쉬운 정적 페이지로 제공한다. 기존 튜토리얼과 유사하게 해당 프로젝트의 GitHub Pages를 사용한다.
- `docs/v2/INDEX.md`: 설정, 데이터 집계, 단계별 검증, 전체 예측, 조건·언어·정답별 통계, 중간평가, 환경, 가중치 출처, 설치 검사, 로그를 분류한 자료 안내.
- `docs/v2/logs/`: 기록된 v1/v2 학습 및 단계별 평가 로그의 공개용 사본. 개인 홈 경로와 터미널 제어문자만 정리하고 수치는 보존한다. 변환 전후 SHA-256과 출처를 manifest에 기록한다.
- `docs/figures/`: 표준 plotting 도구로 만든 학습 loss/검증 추이, 기존 세 평가 항목의 v1/v2 비교 그림. 중간 표본을 최종 전체 점수처럼 그리지 않는다.
- README: 세 항목 전후 표, 설치, 데이터/모델 요약, 블로그·실험 자료의 바로가기.

## 글에 반드시 설명할 내용

1. 사진 여섯 장과 지시에서 A–F/NONE을 선택하는 문제. 중심 대상 기준이며 이미지 속 모든 개체를 세는 것이 아님.
2. 원본 Tiny ImageNet → 40개 클래스 검토 → 작은 bbox/정확 중복 제거 → 사진 단위 분할 → 2×3 격자 → 의미 프로그램과 지시 생성 → 유일한 정답 검사.
3. v2의 원본12,830장, 격자4,825장, 학습예제37,632개, 서로 다른 문장36,328개의 차이. 12유형×2언어×6표현, 수사·방향 어휘, 반사실 대조쌍.
4. Qwen3.5-4B + LoRA + Clef head. Qwen이 자유 답변을 생성하는 구조가 아님. 학습 대상/동결 부분, LoRA 식, 64,511,492 / 4,603,777,028 = 약1.40%의 계산.
5. 왜 사전학습 VLM은 적은 추가 epoch로 적응할 수 있는지. 기존 ImageNet 시각 특징과 이미지·언어·지시 학습의 차이. 해당 설명은 가설/일반 원리이며, 이번 실험에서는 pure Qwen 대조군을 실행하지 않았음을 분명히 한다(사용자 취소).
6. v1에서 표현과 두 조건을 보류한 이유, 실사용 목표에 맞춰 v2에서 모두 학습하도록 변경한 이유. 원본 평가 사진은 여전히 학습에서 제외.
7. v1 선택step2400에서 이어서 학습한 v2. batch8×4704=37632, 추가1epoch의 의미, 실제완료step과 검증으로 선택된배포step의 차이, 전체run시간과 선택시점의 노출량 구분.
8. 실제RTX4070TiSUPER16GB/Windows/Ryzen9800X3D/RAM64GB, 학습률·양자화·메모리·시드·검증/보정 구성. 사용자 최초추정5070Ti를 실제장비로 쓰지 말 것.
9. 사용자가 원한 기존 세 항목의 같은1120문제 전후표:79.29%,67.77%,54.82% → 실측v2 → %p변화. 새v2_test2016의 별도비교와 섞지 않음.
10. 중간56문제 평가와 전체평가 차이, CPU/CUDA 차이, test관찰 후 하이퍼파라미터/선택기준을 바꾸지 않은 사실. 추정이나 목표를 실측으로 표시하지 않음.
11. 개수분기/행필터후이동 등 조건별 결과와 실제오답, 확률보정이 정확도를 직접 올리는 것이 아니라는 점, 새프로세스CPU/CUDA재로딩 차이.
12. Qwen/HuggingFace 기본모델과 GitHubRelease LoRA/head의 다운로드위치·크기·고정revision·hash, 캐시가 재실행을 빠르게 하는 이유, Mac미검증과메모리제약.
13. 원본로그에 없는 배치별 이미지·예측을 재구성해 과거기록인 것처럼 만들지 않음. 기록된10step 간격의loss/history, 검증예측, 최종테스트예측과 소스ID를 공개.

## 완료 순서

사용자가 강조한 핵심 교훈: v1의 제한과 v2의 보완을 모두 본문에 담고, VLM의 시각·언어 표현을 재사용하여 작업에 맞는 데이터를 추가했을 때 짧은 추가 학습으로 적응할 수 있다는 장점을 설명한다. 단, 최종 전체 평가를 근거로 삼고 표본 중간 결과는 분리한다. 데이터의 의미·정답 일관성, 표현/조합의 범위, 사진 분리의 역할을 함께 설명한다. 이번 사례에서 보인 적응 효과를 모든 새로운 작업에 대한 보장이나 사전학습 모델만의 인과적 효과로 과장하지 않는다. v1→v2의 데이터 변화, 같은 문제 전후 비교, 시간과 학습량을 하나의 흐름으로 보여 준다.

학습과 평가가 끝나면 `write_v2_report.py` 결과를 기준으로 글의 수치를 채운다. 모든 표를 JSON과 대조하고 자료 manifest를 생성한 후 정적 페이지를 빌드/검사한다. GitHub 코드·모델 release·README·로그·블로그가 모두 실제로 공개되고 링크가 동작하는지 확인한 뒤 완료를 보고한다. 최종 작업에 블로그가 추가되었으므로 모델배포만 끝났다고 heartbeat를 종료하지 않는다.
